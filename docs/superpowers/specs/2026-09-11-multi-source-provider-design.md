# 多音源 Provider 重构 · 设计规格

> 日期：2026-09-11
> 关联：[ROADMAP.md](../../../ROADMAP.md)（v1.2 多音源）、[DESIGN.md](../../../DESIGN.md)
> 状态：已确认方向，待实施

## 1. 背景与目标

乐府当前只支持汽水音乐：音源识别、本地歌词、切歌判定三处都写死了汽水（com.soda.music）。内录链路本身（BlackHole 抓系统声音 → 静音切分 → LAME 编码 → ID3 标签）与音源无关。

目标：把代码结构重构成以「音源档案」为中心的可扩展结构，使「适配一个新的音乐软件」= 新增一份档案（可选带一个本地歌词解析器），而不改动引擎。先完成结构重构并把汽水等价迁移，保证现有行为不变；之后逐个接入其他软件。

## 2. 范围

### 做
- 引入「音源档案」这一纯数据模型：标识、显示名、bundle 集合、播放判定方式、切歌控制通道、确认节奏、可用的歌词后端。
- 引入「音源登记处」：登记所有内置音源，按系统上报的 App 标识解析出音源，并按「已启用音源集合」过滤。
- 把监听层改为不写死汽水：拿到系统「正在播放」时同时拿到是哪个 App。
- 歌词抓取按「音源本地后端 → 自建缓存 → LRCLIB → 网易云」分级组合；没有本地后端的音源自动跳过第一步。
- 设置页新增「音源」分区（可勾选列表），默认只启用汽水。
- 界面与文案从「汽水」泛化为「你的音乐软件」；成品/队列标明来源平台。
- 把汽水按新结构等价迁移，行为保持不变。

### 不做
- 不解析各软件私有数据库或私有接口来补元数据（明确不做 B 方案）。元数据一律来自系统「正在播放」。
- 不做运行时动态插件加载（C2）；但接口保持以后可自然演进到目录扫描。
- 不在本期细化「多个播放器同时播放时的归属策略」；以系统「正在播放」为唯一事实来源。
- 不改动录制、切分、编码、标签、落盘命名与编码策略。

## 3. 术语

- **音源档案**：描述一个音乐软件的全部差异，纯数据，可单测。
- **音源登记处**：音源档案的集合与解析逻辑；是唯一需要登记新音源的地方。
- **本地歌词后端**：某个音源自带的本地歌词解析能力（如汽水的 KRC 逐字）。可有可无。
- **通用歌词链**：自建缓存 → LRCLIB → 网易云的在线/缓存链路。

## 4. 行为约定

### 4.1 音源识别
系统「正在播放」信息中携带客户端 App 标识。监听层把它一并上报；登记处据此解析音源。解析不到的 App 视为不支持。

### 4.2 是否录制
只有解析出的音源在「已启用集合」内才参与录制与挂机监听。默认已启用集合仅含汽水。

### 4.3 切歌判定
由音源档案决定：轮询间隔、标题需要连续稳定几拍才算确认、如何判断「真的在播」（优先播放速率；速率缺失时才用进度推进）。汽水沿用现行参数与行为。

### 4.4 切歌控制
由音源档案声明控制通道（系统媒体控制 / 命令行通道 / 不支持）。失败时给出明确提示，且不谎报成功。汽水沿用现行通道。

### 4.5 歌词
按顺序：音源本地后端（可逐字，零联网）→ 自建缓存 → （非离线时）LRCLIB → （允许兜底且非离线时）网易云。抓到即回写自建缓存。离线模式下只用本地后端与自建缓存。抓不到就清空，不残留上一首。

### 4.6 多播放器
以系统「正在播放」为准；该 App 不在已启用集合则不录。多个软件同时出声的细化归属策略不在本期范围。

### 4.7 元数据
歌名/歌手/专辑/时长/封面一律来自系统「正在播放」。个别音源上报字段缺失（如汽水 elapsed 恒为 0）时，由该音源档案声明，界面据此退化显示。

## 5. 概念结构

- **音源档案（纯数据 + 解析）**：放在 LefuCore，可单测；包含 bundle 解析与已启用过滤。
- **音源登记处（App 侧）**：内置音源清单，一个软件一个文件；提供按 App 标识取音源的能力。
- **歌词后端**：一个协议 + 通用在线实现 + 各音源本地实现；音源档案引用后端标识。
- **监听改造**：上报「正在播放事实 + App 标识」，不做歌名判断（维持现有职责边界）。
- **设置与界面**：音源勾选、来源徽章、文案泛化。

## 6. 设置与界面

- 设置新增「音源」分区：列出内置音源（图标 + 名称 + 开关），默认仅汽水开启；附一句说明「只录制勾选的软件，避免误录视频/播客」。
- 采诗页空态、指南、菜单栏文案泛化为「你的音乐软件」。
- 队列行与成品可显示来源平台；汽水在默认单源时视觉不变。

## 7. 迁移策略

先搭结构、再把汽水等价迁移：监听、歌词、判定、控制全部走音源档案，但参数与行为与现状逐项一致。验收以「录汽水的一切现状不变」为准，再逐个接入新音源。

## 8. 验收标准

1. 汽水录制全链路行为与改造前一致（切歌确认、进度退化显示、本地 KRC 逐字、离线、挂机监听、切歌控制）。
2. 系统「正在播放」为非启用音源时，不录制、不误开。
3. 新增一个音源只需：新增其档案文件（可选本地歌词后端）+ 登记处一行，不改引擎其他部分。
4. bundle 解析与已启用过滤等纯逻辑有单元测试覆盖。
5. 默认设置下用户可见行为与改造前一致。

## 9. 风险与对策

- **回归风险**：三处耦合点同时改动。对策：汽水等价迁移 + 纯逻辑测试 + 分步提交，每步可编译可验证。
- **本地库不可测**：本机无 XCTest，App 侧逻辑难以本地自动化验证。对策：把可测逻辑尽量下沉到 LefuCore；App 侧靠编译通过与手动烟测；CI 跑 LefuCore 测试。
- **字段差异**：不同音源上报字段不一致。对策：差异全部显式写进档案，界面按档案退化，不做隐藏假设。
